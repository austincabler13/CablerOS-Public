# CablerOS Security & Vulnerability Disclosure Policy — DRAFT

**Status:** Draft  
**Draft date:** September 29, 2026

## Reporting

Security vulnerabilities affecting CablerOS should be reported privately to the CablerOS Project before public disclosure.

A public reporting address or security portal will be added before production release.

Reports should include, when reasonably available:

- affected version;
- description of the vulnerability;
- reproduction information;
- expected security impact; and
- relevant logs or technical details.

## Coordinated Disclosure

The reporter and CablerOS should work together to establish a reasonable public-disclosure date based on severity, exploitability, remediation complexity, and user risk.

There is no single fixed disclosure deadline in this draft. The goal is a mutually agreed date appropriate to the vulnerability.

## Research

Good-faith debugging, inspection, interoperability analysis, and security research are permitted subject to applicable law and the CablerOS License.

This policy does not authorize access to systems, data, accounts, or services that the researcher is not otherwise authorized to access.

## Researcher Credit

CablerOS should publicly credit the first person or team whose valid vulnerability report is received by CablerOS, unless that reporter requests anonymity.

A later duplicate does not receive primary-discoverer credit merely because it was publicly posted first.

Only valid reports accepted by CablerOS qualify for promised public credit under this policy.

## Emergency Repository Actions

A third-party package may be removed immediately from an official CablerOS repository when CablerOS reasonably identifies an active security threat.

The developer may appeal after the emergency action.

Ordinary policy disputes and non-security removals should use the normal repository review process rather than emergency removal.
